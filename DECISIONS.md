INTRADAY VAR ENGINE - DECISIONS

Part I records the decisions as implemented (2026-11-22). Part II is the initial minimal scope
(2026-10-14), kept as written: the project went beyond it where Part I says so.

======================================================================
PART I - DECISIONS AS IMPLEMENTED (2026-11-22)
======================================================================

I.1 ENGINES

Three engines, one per VaR technique, built and tested on their own, plus a shared library:

    ewma/             portfolio engine: EWMA-N (ref) (RiskMetrics), EWMA-N, EWMA-t
    garch_t/          portfolio engine: GARCH(1,1)-t per asset, dynamic correlation, EVT tail
    realized_caviar/  single-instrument engine: Realized-CAViaR against matched EWMA-N,
                      EWMA-t and GARCH-t baselines (the comparison of the research question)
    common/           the common model interface, the RiskMetrics baseline, the jump filter

The portfolio engines went beyond the minimal scope (Expected Shortfall, EVT tail, option book
with Monte Carlo revaluation, overnight risk) because they are the risk-desk view of the problem;
the research question is answered by realized_caviar, where the three models share one instrument,
one boundary and the same targets.

I.2 THE OPEN DECISIONS OF PART II (section 11)

A. Market: B3 equities (15 stocks), plus a synthetic market with the same grid and scripted
   events (data/synthetic), for experiments with a known truth.
B. Data: no free source of 5-second B3 history exists; the shared data are 15-minute bars
   (data/b3_real, 87 sessions, extended by garch_t/source/tools/fetch_b3_yahoo.py).
C. Temporal configuration: the experiments run on the shared 15-minute grid (forecast and update
   every 15 minutes, a one-bar horizon). The target grid (5-second sampling, 1-minute updates,
   5-minute horizon) is reachable by configuration in every engine: realized_caviar's
   high-frequency mode; ewma and garch_t aggregate 5-second samples into bars (--resample) and
   reach a 5-minute VaR every minute with five runs on 5-minute grids one minute apart.
D. Instruments: realized_caviar evaluates each stock separately; the portfolio engines model the
   15 stocks jointly.

I.3 COMMON DECISIONS (the same in every engine)

    Estimation window       40 sessions, fixed (half of the sessions if the file has fewer)
    Calibration             daily, at the end of each session, on the rolling window; no
                            optimization in the per-bar path
    Returns                 first bar of a session ln(close/open) (overnight gap excluded);
                            a return spanning k bars divided by sqrt(k)
    Intraday pattern        returns divided by a per-slot "U" factor estimated on the window
    Data protection         the shared causal jump filter (common/): an isolated jump is held one
                            bar, removed if the next bar undoes it, let in at full size otherwise;
                            jumps of several stocks together are kept. ewma adds its
                            data-quality layer (arrival rules, frozen quotes, NORMAL / DEGRADED /
                            FREEZE modes)
    Scoring                 forecasts scored on the prices as printed (the protection changes
                            what the models see, never the outcomes)
    Baseline                EWMA-N (ref), RiskMetrics, one implementation (common/)
    Models                  behind riskcommon::PortfolioModel in the portfolio engines; a new
                            model is one class plus its registration
    Backtest                Kupiec, Christoffersen, Basel traffic light, Berkowitz, Acerbi-Szekely
                            (ES); pinball loss and Diebold-Mariano with Holm correction in the
                            matched comparison

I.4 EVALUATION

The architecture of the three engines is evaluated with ATAM (atam/): utility tree, scenarios
measured on every engine, scorecard, risks, sensitivity points, trade-offs and non-risks, all
regenerated by atam/run.bat.

======================================================================
PART II - INITIAL MINIMAL SCOPE (2026-10-14)
======================================================================

1. GOAL

Implement and compare three intraday VaR models in a low-latency C++ engine:

1. EWMA-Normal
2. GARCH-t
3. Realized-CAViaR

The focus is the trade-off between statistical quality and computational cost.

Expected Shortfall / CVaR is out of scope.

2. MODELS

2.1 EWMA-Normal

Purpose:
Traditional low-cost baseline.

Variance:

    sigma_t^2 =
        lambda * sigma_(t-1)^2
        + (1 - lambda) * r_t^2

VaR:

    VaR_t =
        exposure_t * z_alpha * sigma_t

2.2 GARCH-t

Purpose:
More sophisticated volatility-model baseline with heavy tails.

Variance:

    sigma_t^2 =
        omega
        + alpha * r_(t-1)^2
        + beta * sigma_(t-1)^2

Innovations:

    z_t ~ Student-t(nu)

VaR is obtained from the conditional volatility and Student-t quantile.

2.3 Realized-CAViaR

Purpose:
Main model.

Initial specification:

    q_(t+1) =
        beta_0
        + beta_1 * q_t
        + beta_2 * |R_t|
        + beta_3 * sqrt(RV_t)

where:

    q_t
        Conditional lower-tail return quantile.

    R_t
        Aggregate return over the information window.

    RV_t
        Realized variance computed from higher-frequency returns:

            RV_t = sum_j r_(t,j)^2

    beta_0 ... beta_3
        Parameters estimated offline by minimizing quantile loss.

For 99% VaR:

    tau = 0.01

The model directly estimates the 1% conditional return quantile instead
of estimating volatility and assuming a return distribution.

3. INITIAL TIME CONFIGURATION

Working configuration:

    VaR confidence level:        99%
    VaR forecast horizon:       5 minutes
    Forecast update frequency:  1 minute
    Market sampling interval:   5 seconds
    Realized-measure window:    5 minutes

Operational forecasts may overlap.

For statistical backtesting, the primary evaluation should use
non-overlapping 5-minute observations when required by the test.

6. CALIBRATION

Model parameters are calibrated offline.

EWMA-Normal:
lambda is fixed or calibrated from training data.

GARCH-t:
estimate omega, alpha, beta, and nu.

Realized-CAViaR:
estimate beta_0, beta_1, beta_2, and beta_3 by minimizing pinball /
quantile loss.

No numerical optimization is performed in the online hot path.

7. BACKTESTING

All three models must be evaluated on the same out-of-sample periods.

Required statistical metrics:

    - VaR exception rate
    - Kupiec unconditional coverage test
    - Christoffersen independence test
    - Christoffersen conditional coverage test
    - quantile / pinball loss

Optional:

    - Dynamic Quantile test

8. PERFORMANCE EVALUATION

Required:

    - time per model update
    - p50 latency
    - p95 latency
    - p99 latency
    - throughput
    - memory / state size

The main comparison is:

    statistical quality
            versus
    computational cost

9. DATA QUALITY

Keep data-quality handling minimal.

Required checks:

    - invalid timestamps
    - duplicate observations
    - out-of-order observations
    - missing / stale data
    - invalid prices

Extreme but valid market returns must not automatically be discarded.

A complex dq_score and NORMAL / DEGRADED / FREEZE state machine are not
required for the first version.

10. OUT OF SCOPE

For the first version:

    - Expected Shortfall / CVaR
    - Monte Carlo VaR
    - EVT
    - neural-network models
    - multi-factor covariance models
    - distributed deployment
    - Kafka / Redpanda
    - REST / WebSocket APIs
    - dashboards
    - complex alerting
    - complex data-quality scoring
    - production persistence

11. OPEN DECISIONS

Only the following decisions are still required before implementation:

A. Market and instrument
Example: B3 equity, B3 future, US equity, crypto.

B. Historical high-frequency data source
Required granularity should support approximately 5-second sampling.

C. Confirm the working temporal configuration:
confidence = 99%
horizon = 5 min
update = 1 min
sampling = 5 s
realized window = 5 min

D. Confirm whether the first implementation should use:
one instrument only
or
multiple independent instruments evaluated separately.

A true multi-asset portfolio model is outside the minimal scope.

12. RESEARCH QUESTION

Does Realized-CAViaR provide materially better intraday VaR forecasts
than EWMA-Normal and GARCH-t while retaining sufficiently low
computational cost for real-time execution in C++?
